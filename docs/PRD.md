## 1. 项目概述

本系统是一个面向**国内航线**的航空票务管理 Web 应用，模拟携程类 OTA 平台的核心数据库与业务流程。系统服务两类角色：**用户**（负责购票、退改、查询订单）与**管理员**（负责城市/机场/航司/航班/航班实例/票价/售票记录等基础数据维护）。

系统的核心价值在于以严谨的关系模型承载票务领域的复杂规则——多舱位多票价定价、阶梯式退改签费率、并发售票防超卖、中转联程推荐——并通过分层架构、事务控制、参数化查询保证数据一致性与安全性。

本项目作为数据库课程作业的目标在于：

- 充分展示 ER 建模、范式化、复合主键/外键、约束设计的能力；
- 展示事务、行锁、索引、视图等数据库核心特性在真实业务场景下的应用；
- 实现一套从数据建模到 Web 交互的完整闭环，且代码结构清晰可维护。

## 2. 术语表

| 术语                           | 定义                                                         | 例子                                            |
| ------------------------------ | ------------------------------------------------------------ | ----------------------------------------------- |
| **航班（Flight）**             | 一条**抽象的航线计划**，由航班号唯一标识，不含具体日期。描述"每周哪几天，从哪起飞，到哪降落，几点起几点到，用什么机型"。 | CA1234，每周一三五，PEK 08:00 → SHA 10:30，B738 |
| **航班实例（FlightInstance）** | 航班在**某个具体日期**的一次执行，是售票和余票统计的最小单位。 | CA1234 在 2026-05-10 的执行                     |
| **舱位（Cabin Class）**        | 物理舱位等级，本项目仅区分两类：经济舱、头等舱。             | 经济舱                                          |
| **票价类型（Fare Type）**      | 同一舱位下的**销售档位**，用于区分标准票、特价票等。每个档位有独立库存。 | 经济舱-标准、经济舱-特价                        |
| **舱位定价（CabinPrice）**     | 某航班实例下，某舱位某票价类型的**售卖单元**：含价格与可售座位数。 | (实例 X, 经济舱, 特价) → 价格 600，剩余 5 张    |
| **客票（Ticket）**             | 一个具体乘客在某航班实例某舱位上的**乘机凭证**，是退改的最小操作对象。 | 票号 T20260510001                               |
| **订单（Order）**              | 一次购买行为的容器，可包含多张客票（同行人）。               | 订单 O20260509999 含 3 张票                     |
| **乘机人（Passenger）**        | 实际乘机的人（可与下单用户不同），按证件号唯一识别。         | 张三，身份证 110......                          |
| **临近机场**                   | 与某城市存在便捷地面交通连接、但不属于该城市行政区划的机场，用于"无直飞"场景下的替代推荐。 | 苏州 → 上海虹桥 / 上海浦东                      |
| **中转联程**                   | 由两段（含以上）相邻航段拼接而成的行程，需满足最小衔接时间约束。 | 北京 → 西安 → 昆明                              |

## 3. 角色与权限

系统有两类用户：**普通用户**与**管理员**。两类用户使用各自独立的 Web 入口，登录后跳转到角色对应的主页。

### 3.1 角色定义

- **普通用户**：在系统注册的旅客，可维护个人信息、绑定多个乘机人、搜索航班、下单购票、查询订单、申请退改签。
- **管理员**：系统运营人员，负责基础数据治理。管理员应默认拥有对于所有基础数据的访问和增改权限。

### 3.2 权限矩阵

| 功能                     | 用户            | 管理员 |
| ------------------------ | --------------- | ------ |
| 注册账号                 | ✅               | ❌      |
| 登录                     | ✅（用户端入口） | ✅      |
| 维护个人/乘机人信息      | ✅（仅本人）     | ❌      |
| 搜索航班                 | ✅               | ✅      |
| 下单购票                 | ✅               | ❌      |
| 查询自己的订单           | ✅               | —      |
| 申请退改签               | ✅（仅本人订单） | ❌      |
| 城市/机场/航司/机型 CRUD | ❌               | ✅      |
| 航班/航班实例 CRUD       | ❌               | ✅      |

> **权限校验位置**：业务逻辑层在执行任何写操作前，先查 `admin_permission` 表确认管理员对目标资源有权限；前端根据权限隐藏不可见入口（仅做体验优化，安全依赖后端校验）。

## 4. 功能模块清单

系统业务逻辑层划分为 6 个模块，覆盖票务系统的完整闭环。

### 4.1 用户与权限模块

- **U1** 用户注册（手机号 + 密码 + 昵称，密码 bcrypt 加盐哈希）
- **U2** 用户登录（用户端入口）
- **U3** 管理员登录（管理端独立入口）
- **U4** 修改个人信息（昵称、密码、手机号）
- **U5** 乘机人管理（增/删/改/查本用户绑定的乘机人列表）
- **U6** 退出登录

### 4.2 基础数据维护模块

- **A1** 城市表 CRUD（含临近机场关系维护）
- **A2** 机场表 CRUD
- **A3** 航空公司表 CRUD
- **A4** 机型表 CRUD（座位配置）
- **A5** 航班表 CRUD（含起飞/到达机场、航站楼、经停、每周飞行日）
- **A6** 航班实例 CRUD：单条创建 + **按航班批量生成未来 N 天实例**
- **A7** 舱位定价 CRUD（按 `(实例, 舱位, 票价类型)` 三元组维护价格与可售座位数）

### 4.3 航班查询模块

- **F1** 三类候选合并搜索：用户输入出发城市、到达城市、出行日期，系统并行返回：
  - **直飞航班**（优先展示）
  - **中转方案**（由 4.6 模块提供）
  - **临近机场替代方案**（出发或到达替换为临近机场）
- **F2** 多条件筛选：航司、舱位、起飞时间段、是否经停
- **F3** 排序：按价格、总时长、起飞时间升降序
- **F4** 航班详情查看：含经停信息、各舱位/票价类型当前价格与剩余座位数

### 4.4 订单与购票模块

- **O1** 创建订单：选定航班实例 + 舱位 + 票价类型 + 录入若干乘机人，下单
- **O2** **下单事务**：在单个数据库事务中：
  1. 校验乘机人未在同一航班实例上已购票（去重）
  2. `SELECT ... FOR UPDATE` 锁定 cabin_price 行，校验 `available_seats >= 申请数`
  3. 扣减 `cabin_price.available_seats` 与 `flight_instance` 的对应余票汇总字段
  4. 插入 `aptorder` 记录（status='待支付'，记录 `created_at`）
  5. 为每位乘机人插入 `ticket` 记录（status='有效'）
- **O3** 模拟支付（无真实支付对接）：用户点击"支付"，订单 status → '已支付'
- **O4** **超时释放**：定时任务每分钟扫描 `created_at < now() - 15min` 且 status='待支付' 的订单，事务内回补库存 + 订单 status → '已取消' + 关联客票 status → '已退'
- **O5** 订单查询：用户查看自己所有订单（按时间倒序，可按状态筛选）
- **O6** 订单详情：展示订单含的所有客票及对应航班信息

### 4.5 退改签模块

- **R1** 退票申请：用户对单张客票发起退票
  - 计算手续费（按 4.6.2 规则）
  - 事务内：客票 status → '已退'，cabin_price 库存 +1，flight_instance 余票汇总 +1，写 refund_change 记录
  - 订单状态联动：所有票退完 → '已完成退款'，部分退 → '部分退款'
- **R2** 改签申请：用户对单张客票发起改签到新航班实例
  - 等价于"作废旧票 + 生成新票"
  - 事务内：旧票 status → '已改签作废'，旧实例库存 +1；新实例库存 -1，生成新 ticket（status='有效'）；refund_change 记录中 `new_ticket_no` 填新票号；用户补差价或获得退款
- **R3** 退改记录查询：用户查看自己的退改历史

### 4.6 中转联程推荐模块

- **C1** 直飞匹配：基于 `flight` 表的起飞/到达机场过滤。（具体而言，如果城市拥有机场，那么城市临近机场的表中，该机场对应城市距离为0，将匹配距离为0的机场确定为直飞方案）。
- **C2** **中转匹配**：航班实例自连接，约束：
  - 第一段到达机场 = 第二段起飞机场
  - 第二段起飞时间 - 第一段到达时间 ∈ [最小衔接时间, 最大衔接时间]
  - 总时长不超过阈值
  - 仅返回两段都有可售座位的组合
- **C3** 临近机场替代：若出发城市或到达城市的"位于"机场无直飞（也就是不存在距离为0的机场），则查询其临近机场作为替代起点/终点

## 5. 核心业务流程

### 5.1 购票主流程

```
用户登录
  ↓
输入出发城市 + 到达城市 + 日期 → 触发航班查询
  ↓
航班查询模块并行返回三类候选（直飞 / 中转 / 临近机场）
  ↓
用户排序筛选 → 选定航班实例 + 舱位 + 票价类型
  ↓
录入乘机人信息（从绑定列表选择或新增）
  ↓
[事务开始]
  校验余票 → 扣减库存 → 创建订单(待支付) → 创建客票(有效)
[事务结束]
  ↓
跳转支付页（15 分钟倒计时）
  ↓
  ├─ 用户支付成功 → 订单 → '已支付'
  └─ 超时未支付 → 后台任务回补库存 → 订单 → '已取消' → 客票 → '已退'
```

### 5.2 退票流程

```
用户在订单详情页选择某张客票 → 申请退票
  ↓
系统按"距起飞时间"档位计算手续费
  ↓
[事务开始]
  客票 status → '已退'
  cabin_price.available_seats += 1
  flight_instance 余票汇总 += 1
  插入 refund_change(op_type='退票', fee=X, new_ticket_no=NULL)
  根据订单内剩余有效票数更新订单 status:
     - 全退 → '已完成退款'
     - 部分退 → '部分退款'
[事务结束]
  ↓
返回退款金额 = actual_price - fee
```

### 5.3 改签流程

```
用户选择某张客票 → 申请改签 → 选定新航班实例 + 舱位 + 票价类型
  ↓
系统计算手续费 + 新票价差额
  ↓
[事务开始]
  校验新实例余票
  旧客票 status → '已改签作废'
  旧 cabin_price.available_seats += 1（旧实例余票汇总 += 1）
  新 cabin_price.available_seats -= 1（新实例余票汇总 -= 1）
  生成新 ticket（status='有效'，order_no 仍指向原订单）
  插入 refund_change(op_type='改签', fee=X, new_ticket_no=新票号)
[事务结束]
  ↓
用户支付差价或获得退差价
```

## 6. 关键业务规则

### 6.1 余票扣减与释放（防超卖）

- **扣减时机**：用户点击"下单"瞬间，**在数据库事务内**通过 `SELECT ... FOR UPDATE` 锁定 `cabin_price` 对应行，再校验并扣减 `available_seats`。
- **释放时机**：订单创建后 15 分钟内未支付 → 后台定时任务（每分钟扫描）事务内回补库存。
- **退改触发的释放**：详见 4.5。
- **库存的双重表达**：
  - 精细库存：`cabin_price.available_seats`（按票价类型）
  - 汇总库存：`flight_instance.economy_left / first_left`（按舱位）
  - 二者通过事务内同步更新保持一致；汇总值仅用于查询展示。
- **隔离级别**：使用 InnoDB 默认 REPEATABLE READ；下单与退改操作必须使用 `SELECT ... FOR UPDATE`，不允许使用乐观锁。

### 6.2 退改签费率规则

按"操作时间距航班实例计划起飞时间"分档计算手续费比例（基数 = 客票 `actual_price`）：

| 距起飞时间 | 退票手续费率 | 改签手续费率 |
| ---------- | ------------ | ------------ |
| ≥ 24 小时  | 10%          | 5%           |
| 4–24 小时  | 30%          | 15%          |
| 2–4 小时   | 50%          | 30%          |
| < 2 小时   | 不可退       | 不可改       |
| 已起飞     | 不可操作     | 不可操作     |

> 实际比例可按需调整，但**写死在配置文件或常量类中**，不在数据库中表达（简化实现）。

### 6.3 价格规则

- **挂牌价**：`cabin_price.price`，由管理员维护，可随时调整。
- **成交价**：`ticket.actual_price`，下单时刻 `cabin_price.price` 的快照。
- **退改手续费**始终以**成交价**为基数，与后续挂牌价变动无关。
- **特价票**：作为独立票价类型存在（如 `fare_type='特价'`），有独立库存与价格，不享有学生折扣等额外规则（本项目简化）。

### 6.4 中转换乘规则

- **最小衔接时间（MCT）**：60 分钟（同机场）。
- **最大衔接时间**：6 小时（避免出现过夜中转）。
- **最大总时长**：12 小时。
- **不限同航司**：允许跨航司中转。
- **不考虑行李直挂**：本项目不涉及。
- **仅支持单次中转**：不递归推荐两次以上中转。

### 6.5 临近机场规则

- 定义在 `city_near_apt(city_name, iata_code, distance)` 表中。
- "临近"语义：与该城市存在便捷地面交通、距离 ≤ 200 km 的非本市机场。
- 由管理员手工维护（不自动计算）。
- 触发条件：出发或到达城市无直飞航班、或主动开启"包含临近机场"选项。

### 6.6 数据完整性规则（约束层）

- 航班实例的剩余座位数初始化时按机型座位数填充。
- 各舱位剩余座位数 ≥ 0（CHECK 约束）。
- 同一乘机人在同一航班实例上仅能有一张"有效"状态的客票（应用层校验，因为状态过滤无法用唯一约束直接表达）。
- 经停顺序在同一航班内唯一（联合唯一约束）。

## 7. 状态机定义

### 7.1 订单状态机（aptorder.status）

```
                 [创建]
                    ↓
                 待支付 ──[15分钟超时]──→ 已取消（终态）
                    │
                    ├──[支付成功]──→ 已支付
                    │                   │
                    │                   ├──[全部客票退票]──→ 已完成退款（终态）
                    │                   ├──[部分客票退票]──→ 部分退款 ──[剩余全退]──→ 已完成退款
                    │                   └──[所有票完成乘机]──→ 已完成（终态）
                    │
                    └──[用户主动取消]──→ 已取消（终态）
```

| 状态       | 含义                       | 可达后继                       |
| ---------- | -------------------------- | ------------------------------ |
| 待支付     | 订单已创建，库存已锁定     | 已支付 / 已取消                |
| 已支付     | 已扣款                     | 部分退款 / 已完成退款 / 已完成 |
| 部分退款   | 订单内有票被退，仍有有效票 | 已完成退款 / 已完成            |
| 已完成退款 | 所有票已退（终态）         | —                              |
| 已完成     | 所有票已乘机（终态）       | —                              |
| 已取消     | 未支付即取消（终态）       | —                              |

### 7.2 客票状态机（ticket.status）

```
                 [下单]
                    ↓
                  有效 ──[退票]──→ 已退（终态）
                    │
                    ├──[改签]──→ 已改签作废（终态，但生成新票）
                    │
                    └──[航班完成]──→ 已使用（终态）
```

| 状态       | 含义                                                   |
| ---------- | ------------------------------------------------------ |
| 有效       | 可用于乘机                                             |
| 已退       | 退票后状态（终态）                                     |
| 已改签作废 | 改签的旧票（终态，refund_change 中关联 new_ticket_no） |
| 已使用     | 已乘机（终态）                                         |

### 7.3 航班实例状态机（flight_instance.status）

```
计划 ──[到达可订时间窗口]──→ 可订 ──[起飞]──→ 已起飞 ──[降落]──→ 已到达（终态）
                                  │
                                  ├──[不可抗力]──→ 延误（可恢复至 可订/已起飞）
                                  └──[管理员操作]──→ 已取消（终态，触发批量退款）
```

## 8. 非功能需求

### 8.1 并发与一致性（核心）

> 这是本项目最重要的非功能需求，直接呼应"数据库及实现"课程的考点。

- **下单防超卖**：必须使用 InnoDB 行锁 + 事务（`SELECT ... FOR UPDATE`）实现。验收方式：编写多线程脚本同时对仅剩 1 张余票的航班实例发起 100 个下单请求，预期仅 1 个成功，其余因库存不足失败。
- **退改的库存回补**：必须在同一事务内完成"修改客票状态 + 库存 +1"，避免出现客票已退但库存未回补的不一致。
- **超时释放**：通过定时任务实现，扫描间隔 60 秒。允许有最多 60 秒的"已过期但未释放"窗口。
- **隔离级别**：默认 REPEATABLE READ，关键事务内使用悲观锁。

### 8.2 安全

- 用户/管理员密码使用 bcrypt 加盐哈希存储，禁止明文。
- 所有数据库查询使用参数化（SQLAlchemy 默认行为），禁止字符串拼接 SQL。
- 登录态通过 session 或 JWT 维持，禁止前端明文存储敏感字段。
- 管理员所有写操作在后端校验 `admin_permission`，前端隐藏仅作体验优化。

### 8.3 性能

- 航班查询响应时间：直飞场景 < 500 ms；中转场景 < 2 s（基于 10 万级航班实例数据）。
- 数据库连接池：最小 5、最大 20 连接。
- 关键索引（详见 SCHEMA.md）：
  - `flight(dep_airport_code, arr_airport_code)`
  - `flight_instance(flight_no, flight_date)`
  - `ticket(order_no)`、`ticket(passenger_id)`
  - `aptorder(user_id, created_at)`

### 8.4 可观测性（弱要求）

- 后端打印关键操作日志（下单、支付、退改）含订单号、用户号、操作时间。
- 不要求接入 APM。

## 9. 范围与非目标

### 9.1 包含的范围

- 国内航线机票预订全流程（搜索 → 下单 → 支付 → 出票 → 退改）
- 三类候选合并搜索（直飞 / 中转 / 临近机场）
- 单次中转推荐
- 多舱位 + 多票价类型（含特价票）
- 阶梯式退改签费率
- 并发售票防超卖
- 管理员基础数据 CRUD + 资源级权限
- 完整的 Web 用户界面（用户端 + 管理端）

### 9.2 明确不做（Non-goals）

- ❌ 国际航线（涉及多时区、多币种、护照校验等复杂规则）
- ❌ 真实支付对接（使用 mock，点击"支付"即视为成功）
- ❌ 值机、选座、行李托运、餐食预订
- ❌ 儿童票、婴儿票、老年票、学生票（票价仅区分"标准 / 特价"两档）
- ❌ 积分、里程、会员等级
- ❌ 税费拆分（票价已含所有税费，单一字段表达）
- ❌ 短信/邮件/推送通知（仅写入数据库通知表，不真实发送）
- ❌ 联程行李直挂、航司联运
- ❌ 两次以上中转
- ❌ 超售策略与候补名单
- ❌ 客服、投诉、评价系统

### 9.3 简化处理

- 退改费率写死在代码常量中，不做"按航司、按舱位、按折扣率"的精细化配置。
- 临近机场关系由管理员手工维护，不做地理距离自动计算。
- 通知模块仅做最小实现（写库 + 用户主动查看）。
